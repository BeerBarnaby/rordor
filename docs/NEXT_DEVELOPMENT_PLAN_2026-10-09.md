# แผนพัฒนาน้องพร้อมรอบถัดไป

วันที่ 9 ตุลาคม 2569

## ขอบเขตรอบเผยแพร่ปัจจุบัน

- ใช้ Prompt ทั้งเว็บ: หัวข้อ 600 ปุ่ม/เมนู 500 เนื้อหา 400
- คงสี โครงหน้า การใช้งานแบบผู้เยี่ยมชม และทุกบทเรียนที่เปิดอยู่
- รวมการปรับหน้าเลือกภารกิจและ motion ที่คอมมิทไว้ก่อนหน้า
- เพิ่มบทอ่าน CPR ผู้ใหญ่ 5 เรื่อง พร้อมแหล่งอ้างอิง AHA/Red Cross
- เนื้อหา CPR ที่เพิ่มใหม่ยังต้องให้ครูฝึกตรวจ ไม่ถือว่าการอนุมัติเนื้อหาเดิมครอบคลุมส่วนใหม่
- ไม่มีการเปลี่ยนฐานข้อมูลหรือสูตร XP ในรอบนี้

## หลักการและเส้นทางผู้ใช้

หน้าแรก → เลือกภารกิจ → ประเมินเหตุ/เรียงลำดับ → สนทนา 1669 → ฝึกจังหวะ CPR → สรุปผล → ทบทวนจุดที่พลาด

AED เป็นบทเสริมในแอป แต่ในเหตุจริงต้องใช้ทันทีเมื่อมีเครื่องและทำตามคำแนะนำ ไม่สื่อว่าควรชะลอใช้เพราะเป็นบทเสริม

ข้อมูลบทเรียนมาจากไฟล์เนื้อหา → แสดงใน LearningCenter → ผู้ใช้บันทึกการทบทวนในเครื่อง ส่วนผลภารกิจใช้ระบบคะแนนเดิม: ผู้เยี่ยมชมบันทึกในเครื่อง ผู้มีโปรไฟล์ส่งผลผ่าน API และคิวรอส่ง ไม่มี XP จากการเปิดหัวข้ออ่านเฉย ๆ

## ระยะ 1 — ความชัดเจนก่อนความสวย

1. ทดลองกับผู้เรียน 5–8 คน: เริ่มภารกิจโดยไม่ช่วยนำ สังเกตว่าเลือกปุ่มแรกได้หรือไม่และสับสนตรงไหน
2. ตรวจทุกหน้าที่ 320/390/768/1440 px รวมการขยายข้อความและข้อความชื่อยาว
3. ปรับการ์ด AED ให้รองจากภารกิจหลักอย่างชัดเจน โดยไม่ซ่อนทางเข้า
4. ลดข้อความซ้ำระหว่างบทอ่าน สรุปขั้นตอน และคำแนะนำหลังฝึก

เกณฑ์ผ่าน: ไม่มีข้อความทับ/ล้น ปุ่มสำคัญแตะง่าย ผู้ทดลองอย่างน้อย 80% เริ่มภารกิจได้เอง เก็บผลจริงก่อนอ้างว่าผ่าน

## ระยะ 2 — การเรียนและ feedback

1. ครูฝึกตรวจบทอ่าน CPR ใหม่ โดยเฉพาะขอบเขตผู้ใหญ่ การหายใจเฮือก และ 30:2
2. สรุปผลเลือกจุดฝึกต่อเพียง 1–2 เรื่อง พร้อมปุ่มไปบทที่เกี่ยวข้อง
3. ตรวจบทสนทนา 1669: ข้อมูลสถานที่ อาการ จำนวนผู้ป่วย และเบอร์ติดต่อ ไม่ทำให้ผู้เรียนเข้าใจว่าโทรจริง
4. พิจารณาภาพตำแหน่งมือเฉพาะเมื่อมีภาพที่ครูฝึกตรวจแล้ว ไม่ใช้ภาพหน้าปกแทนภาพสาธิต

เกณฑ์ผ่าน: ทุกคำแนะนำเชื่อมกับพฤติกรรมที่วัดได้ ไม่กล่าวว่าแอปวัดแรง/ความลึก CPR หรือรับรองทักษะภาคปฏิบัติ

## ระยะ 3 — อุปกรณ์จริงและความทนทาน

1. ทดสอบเสียงบน Android และ iPhone/iPad จริง: เริ่มเสียงจากการแตะ ปิดเสียง สลับแอป และกลับมาฝึก
2. ทดสอบเน็ตหลุด/โหลดใหม่/เปลี่ยนโปรไฟล์: ผลไม่หาย ไม่ส่งซ้ำ และไม่ผูกผลผิดบัญชี
3. ตรวจ leaderboard สองโหมดเสียงและ XP หลังฝึกหลายครั้งด้วยบัญชีทดสอบที่ระบุชัด
4. เพิ่มการตรวจ test/lint/build ในกระบวนการเผยแพร่ และตรวจ error หลัง deploy

เกณฑ์ผ่าน: ผลภารกิจบันทึกครั้งเดียวตามเจ้าของจริง เสียงไม่ค้าง ไม่มี error ที่ขัดขวางการฝึก ทดสอบอุปกรณ์จริงยังไม่เสร็จ

## ระยะ 4 — วัดผลแล้วจึงเพิ่มลูกเล่น

1. วัดจุดออกจากภารกิจและคำถามที่ตอบผิดบ่อย โดยเก็บเท่าที่จำเป็นและไม่ส่งเบอร์โทรเป็น analytics
2. เพิ่ม micro-interaction เฉพาะการเลือก การเปลี่ยนขั้น และผลตอบกลับ รองรับ reduced motion
3. ไม่เพิ่มจังหวะตกแต่งที่แข่งกับ metronome CPR
4. ประเมินความจุด้วย load test ที่ได้รับอนุญาตในสภาพแวดล้อมทดสอบ ไม่อ้างจำนวนผู้ใช้พร้อมกันจากสเปกแพ็กเกจ

เกณฑ์ผ่าน: ทุกการเพิ่มมีปัญหาผู้ใช้รองรับและเปรียบเทียบผลก่อน/หลัง ไม่ออกแบบใหม่ทั้งเว็บโดยไม่มีเป้าหมาย

## ลำดับเริ่มงาน

เริ่มจากระยะ 1 และการตรวจเนื้อหาในระยะ 2 ก่อน จากนั้นทดสอบอุปกรณ์จริง งานใหม่ให้ทดลองในเครื่องและส่งภาพก่อนเผยแพร่ครั้งถัดไป
