# น้องพร้อม — แบบ AED ที่เลือก

วันที่ 6 ตุลาคม 2026

[ไฟล์ Figma](https://www.figma.com/design/0Pdi6Am2mz6z36FchOGeDJ)

## ขอบเขตของรอบนี้

จัดแบบผสมแนว 1 (คู่มือภาคสนาม) และ 3 (ภาพสถานการณ์) ที่ผู้ใช้เลือก ตัวละครการ์ตูนเส้นหนาในชุดฝึกสีเขียวตามภาพอ้างอิง ไม่เปลี่ยนเว็บจริง ไม่ commit หรือ deploy ในรอบนี้

สร้าง 24 หน้าจอ: 8 สถานะ × มือถือ 390 px / แท็บเล็ต 768 px / คอม 1440 px สถานะคือ power, pads, clear, analyzing, shock, no-shock, resume และ complete ขนาดมือถือ clear/shock เป็นหน้าเลื่อนสูง 876 px; ปุ่มหลักอยู่ก่อนท้าย viewport 844 px ในภาพตรวจ ไม่ใช่การทดสอบอุปกรณ์จริง

## เหตุผลในการจัดหน้า

- คำสั่งหลักอยู่บนสุด ต่อด้วยคำอธิบายสั้น แล้วภาพหรือสถานะเครื่อง
- ภาพตัวละครใช้ในขั้นเคลียร์พื้นที่และก่อนช็อก ไม่แทรกทุกหน้า เพื่อไม่แข่งกับคำสั่ง
- มือถือเรียงแนวตั้ง; คอมแยกภาพซ้ายและงานที่ต้องทำขวา ภายในพื้นที่อ่าน 1040 px
- สีครีมเป็นพื้น Navy เป็นข้อความ แดงเป็นปุ่มหลัก เหลืองอ่อนพร้อมข้อความเป็นคำเตือน ไม่พึ่งสีเพียงอย่างเดียว
- ตัวเลขในรายการเป็นลำดับการกระทำ ไม่ใช่แถบตกแต่งนำหน้าข้อความ
- แสดงความคืบหน้า AED เพียงระดับเดียว ไม่ซ้ำ 04/04 กับ 1/5
- analyzing ใช้ปุ่มสถานะ disabled; no-shock ไม่ใช้ปุ่มช็อก; resume บอกว่าการช่วยจริงต้องกลับไป CPR แต่บทเรียนนี้ไปหน้าสรุป
- ไม่แสดงคะแนนทักษะ AED จากการกดผ่านขั้นตอน ไม่เปลี่ยน XP หรือระบบสมาชิก

## โครงสร้างที่แก้ไขได้

ใช้ Figma Skills สร้าง Auto Layout, ตัวอักษร, สีที่ผูกกับตัวแปร และชิ้นส่วนใช้ซ้ำ Header / Action button / Instruction row / Safety notice ปุ่มมี Default, Pressed และ Disabled ภาพการ์ตูนเป็น raster แยกชิ้น; ไม่ได้นำภาพหน้าจอทั้งหน้าไปแปะเป็นงานออกแบบ

ฟอนต์ Figma ใช้ Anuphan ชั่วคราว เนื่องจากตัวเชื่อมไม่พบ LINE Seed Sans TH เว็บไซต์ยังคง LINE Seed Sans TH ต้องตรวจระยะและการตัดบรรทัดอีกครั้งด้วยฟอนต์เว็บก่อนนำขึ้นจริง ห้ามถือว่าเป็นแบบตัวอักษรตรงกันสมบูรณ์แล้ว

## ผลตรวจในรอบนี้

- ตรวจภาพมือถือครบ 8 สถานะ และภาพ clear ของแท็บเล็ต/คอม
- พบและแก้ภาพ/ปุ่มถูกตัดในสองคอลัมน์คอม ตรวจซ้ำแล้วภาพและปุ่มแสดงครบ
- ตรวจขอบเขตชั้นลูกกับขอบหน้าจอทั้ง 24 หน้า ไม่พบชั้นล้นขอบหน้าจอในผลตรวจนี้
- ตรวจตัวอักษรอ่านกลับ: Anuphan ทุกชั้นใน screen review
- ตัวละครแยกชิ้นมี alpha โปร่งใสที่มุมภาพ (ค่า 0) และไม่มีข้อความ UI ติดมา

หลักฐาน: `figma-check-1.png` (มือถือ clear), `figma-check-2.png` (แท็บเล็ต clear), `figma-desktop-final.png` (คอมหลังแก้), `figma-power.png`, `figma-pads.png`, `figma-analyzing.png`, `figma-shock.png`, `figma-no-shock.png`, `figma-resume.png`, `figma-complete.png`

## ยังต้องทำก่อนนำไปใช้จริง

1. ภาพตำแหน่งติดแผ่น AED ยังไม่มีในหน้า pads ต้องใช้ภาพคำแนะนำที่ตรวจเนื้อหาแล้ว ไม่ใช้ภาพการ์ตูนเคลียร์พื้นที่เป็นภาพสอนติดแผ่น ภาพปัจจุบันเป็นภาพประกอบการเคลียร์พื้นที่และไม่ได้แสดงรายละเอียดสาย/แผ่นทั้งหมด
2. แบบนี้ยังไม่ใช่ prototype ที่คลิกครบ flow: ต้องเชื่อมปุ่ม, วิเคราะห์แล้วแตกสองกรณี, ยืนยันออก และเปิดเหตุผลของขั้นตอน
3. ให้ตรวจแบบและฟอนต์ชั่วคราวก่อนแก้เว็บ จากนั้นทดสอบ LINE Seed Sans TH จริงที่ 320/390/768/1440 px
4. ตรวจ keyboard focus, screen reader, reduced motion, contrast และเสียงจริงบนอุปกรณ์ งานตรวจ Figma ไม่รับรอง accessibility ของเว็บ

## ภาพที่ผลิต

ใช้ Creative Production และเครื่องมือสร้างภาพในตัว แยกภาพจากแบบที่อนุมัติ โดยรักษาหน้าตา ชุดฝึก ท่าทาง เส้นหนา และสีเดิม ลบตัวหนังสือ ปุ่ม และกรอบ UI ทั้งหมด ขอพื้นโปร่งใส ไม่มีตราราชการหรือข้อมูลบุคคล

ไฟล์: `assets/prom-aed-clear-v1.png` เป็นภาพที่สร้างด้วย AI ตาม reference ไม่อ้างว่าเป็นงานวาดมือ และยังไม่ได้เชื่อมเข้าหน้าเว็บ

## ขั้นต่อไป

เติมภาพสอนติดแผ่นและต้นแบบการคลิกก่อน จากนั้นจึงนำแบบที่ตรวจแล้วไปปรับ AEDSimulation และส่วนหัวเฉพาะที่เกี่ยวข้อง รักษา state machine, scoring, งานเสียงที่ค้างอยู่ และหน้าอื่นที่ผู้ใช้ยังไม่อนุมัติให้เปลี่ยน
