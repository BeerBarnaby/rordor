## 2. เป้าหมาย

ผู้เรียนเปิดมือถือแล้วรู้ว่าเริ่มตรงไหน ระหว่างฝึกรู้ว่า “ตอนนี้ต้องทำอะไร” และหลังฝึกรู้ว่าควรทบทวนเรื่องใด

ทิศทาง: คู่มือฝึกภาคสนามแบบดิจิทัล — 80% เรียบเพื่อทำงาน + 20% แสดงตัวตนในช่วงที่เหมาะสม ไม่ใช่เปอร์เซ็นต์จำนวนสีที่ต้องคำนวณตายตัว

ข้อผูกพันที่ต้องรักษา:

- Mobile-first แต่ใช้ได้บน iPad และคอมพิวเตอร์
- ทุกบทเรียนเปิด ไม่บังคับสมัครหรือเรียนตามลำดับ
- ชื่อหน่วยใช้ “หน่วยฝึกนักศึกษาวิชาทหาร มณฑลทหารบกที่ 37”
- ไม่ใช้ขีดตกแต่งนำหน้าข้อความหรือแถบสีข้างกล่องแบบที่ผู้ใช้ไม่ชอบ
- คะแนน/XP/ภาพ/เสียงไม่สร้างความเข้าใจว่าเป็นการรับรองทักษะทางการแพทย์

## 3. บทบาทของเครื่องมือ

| เครื่องมือ | งานที่ใช้ | สิ่งส่งมอบ |

| Creative Production | ทำภาพตามพื้นที่ที่ออกแบบไว้ ใช้สไตล์เดียวกัน | เครื่องหมายแบรนด์ ตัวละคร และภาพประกอบที่มีหน้าที่ชัด |

## 4. Flow ผู้เรียนที่ต้องออกแบบ

```text
หน้าแรก → เลือกเริ่มฝึก/ฝึกต่อ → อ่านสถานการณ์สั้น → ลงมือทีละกิจกรรม → สรุปผล → ทบทวนบทที่เกี่ยวข้อง
หน้าแรก → บทเรียน → เลือกบทใดก็ได้ → อ่าน/ดูสื่อ → เลือกฝึก
โปรไฟล์และอันดับเป็นทางเลือก ไม่กั้นสองเส้นทางข้างบน
```

หน้าแรก: CTA หลักหนึ่งปุ่มตามสถานะจริง “เริ่มฝึก” หรือ “ฝึกต่อ” รองลงมาเป็นบทเรียน แล้วจึงผลล่าสุดและ XP/อันดับ ไม่ให้ leaderboard แย่งความสำคัญการฝึก

บทเรียน: ใช้ชื่อและคำกริยาที่ชัด เช่น “เรียนเรื่อง AED” เลข 01–04 เป็นเพียงข้อมูลลำดับ ไม่ใช่สัญญาณเดียวว่ากดได้

ภารกิจ: ชื่อกิจกรรมและความคืบหน้าสั้น → คำสั่งปัจจุบัน → ข้อมูลจำเป็น → ข้อควรระวังเฉพาะขั้น → ปุ่มลงมือ รายละเอียดรองเปิดดูภายหลังได้

สรุป: แยกสิ่งที่วัดจริง สิ่งที่ทบทวนครบ และคำแนะนำ ไม่ให้ XP หรือ celebration ทำให้เข้าใจว่าฝึกผ่านภาคปฏิบัติ

## 5. แผนหน้าจอและเหตุผล

### AED — ทำก่อน

- คำสั่งปัจจุบันเป็นจุดอ่านหลักหนึ่งจุด สถานะเครื่องเป็นข้อมูลรอง ไม่ใช้หัวข้อใหญ่ซ้ำ
- ภาพอยู่เฉพาะเมื่อช่วยเข้าใจงาน เช่น เปิดเครื่อง/ภาพประกอบการติดแผ่น ไม่วางตัวละครขณะวิเคราะห์หรือช็อก
- ข้อห้ามอยู่ก่อนปุ่ม และมีทั้งข้อความกับสัญลักษณ์ ไม่สื่อด้วยสีอย่างเดียว
- ช่วงวิเคราะห์ปิดปุ่มและบอกว่ารอเครื่อง ไม่เพิ่มเกมแข่งเวลา
- ปุ่มเปลี่ยนข้อความตาม state รักษา guards และทั้งสอง branch กลับ CPR
- ภาพสอนตำแหน่งแผ่นต้องมีแหล่งอ้างอิงและผู้ตรวจเนื้อหา ห้ามใช้ภาพเจนเป็นแหล่งความถูกต้อง

### หน้าแรก — ทำหลังเลือกภาษา UI จาก AED

- ลด hero และข้อความโฆษณา ให้เห็นปุ่มหลักใน viewport แรกที่ 390×844 โดยไม่ต้องเลื่อน
- ใช้บริบทฝึกจริงและสถานะจริง ไม่แต่ง “ฝึกครั้งล่าสุด” หรือ “จุดอ่อน” ที่ไม่ได้บันทึก
- ภาพน้องพร้อมมีบทบาทเชิญฝึก ไม่กินพื้นที่เหนือปุ่มหรือกลายเป็นพื้นหลังรบกวนข้อความ

### บทเรียน / 1669 / CPR / ผลสรุป

- บทเรียน: แสดงชื่อ สิ่งที่จะเรียน เวลาโดยประมาณ และปุ่มเข้าบทชัดเจน
- 1669: แยกคำถาม ตัวเลือกที่เลือก และ feedback ให้คนเห็นก่อนตอบ/หลังตอบ ไม่สร้างสายโทรจริง
- CPR: ให้พื้นที่แตะ จังหวะ และจำนวนครั้งเด่นกว่าองค์ประกอบตกแต่ง ตัวช่วยเสียงเป็นทางเลือก
- ผลสรุป: บอกข้อที่ควรฝึกต่อจากข้อมูลจริง มีลิงก์ไปบทที่เกี่ยวข้องก่อนอันดับ

## 6. สี ตัวอักษร และระยะ

เริ่มจาก palette เดิม ไม่เปลี่ยนสีทุกส่วนพร้อมกัน:

- พื้นครีม/ขาว: พื้นอ่านเนื้อหา
- Navy/ดำ: ข้อความ โครงสร้าง และพื้นที่ฝึกจังหวะ
- แดง: primary action และสถานะสำคัญ ไม่โปรยในเลขทุกตัว/คำทุกคำ
- เขียว: ทำครบหรือคำตอบถูก ไม่หมายถึงปลอดภัยทางคลินิก
- เหลือง: คำเตือนที่ต้องอ่านก่อนทำ ไม่ใช้แต่งกล่องทั่วไป

ค่าเริ่มต้นสำหรับแบบร่าง: เนื้อหา 16–18px, หัวข้อส่วน 20–22px, H1 มือถือ 28–32px, line-height ไทยประมาณ 1.5–1.65 และระบบระยะ 4/8/12/16/24/32px ต้องทดสอบจริงก่อนกำหนด final tokens

ใช้ความหนา ตำแหน่ง และพื้นที่ว่างสร้างลำดับก่อนใช้สี; จำกัดข้อความเน้นหนาเฉพาะสิ่งที่ต้องจำ ปุ่มสัมผัสขั้นต่ำ 44×44px ทดสอบ contrast ระดับ AA และข้อความขยาย 200%

## 8. ลำดับดำเนินงานและจุดตรวจรับ

| ระยะ | งาน | จุดตรวจรับก่อนระยะถัดไป |
|---|---|---|
| 0 — เก็บฐาน | แยก diff เสียง, ระบุ commit/deployment, เก็บภาพทุกหน้าหลักและ AED ทุก state | รู้ว่าอะไรอยู่ production อะไรอยู่ local และมีทางคืนเวอร์ชัน |
| 1 — ตรวจ UX | เดิน flow ผู้มาใหม่/กลับมาฝึก/ไม่ล็อกอิน จัดปัญหา P0–P2 | รายการปัญหาอ้างภาพ พร้อมเหตุผล ไม่ใช่ความชอบลอย ๆ |
| 2 — เลือกแบบ | ทำ AED 3 ทางเลือก + ตัวอย่างหน้าแรกในทิศที่สัมพันธ์กัน | ผู้ใช้เลือกหนึ่งทิศ ยังไม่แก้ UI production |
| 3 — Figma | แบบที่เลือกครบ states, มือถือ/iPad/desktop, component/tokens | อ่านลำดับได้ หนึ่ง action หลัก ข้อความและสีอธิบายหน้าที่ได้ |
| 4 — ภาพ | เริ่ม mark และ character หนึ่งตัว จากนั้นภาพสอนที่จำเป็น | ดูบนขนาดใช้งานจริง ผู้ใช้เลือกและผู้ตรวจรับรองภาพสอน |
| 5 — พัฒนา | AED → หน้าแรก → บทเรียน → 1669/CPR → สรุป; PR/commit แยกตามชุด | ผ่าน tests/lint/build + ภาพก่อนหลัง ไม่มี flow/ข้อมูลเดิมเสีย |
| 6 — ทดลองใช้ | ทดลองกับผู้เรียน 5–8 คนและครูฝึก ตรวจเครื่องจริง | แก้จุดอ่านผิด/กดผิด บันทึกผลจริง ไม่อ้าง sample เป็นสถิติทั้งหมด |
| 7 — เผยแพร่ | ให้ตรวจ preview แล้ว deploy ตามคำขอ | ตรวจ production ใหม่และมี rollback target |

ไม่กำหนดวันเสร็จแบบตายตัวก่อนรู้จำนวนหน้าที่เลือกและรอบตรวจภาพ แบ่งส่งเป็นชุดเล็กแทนรอ redesign ทั้งระบบ

## 9. การไหลของข้อมูลและสิ่งที่ไม่แตะในงานภาพ

```text
ข้อมูลบทเรียน/สถานการณ์ → UI กิจกรรม → state/ผลจริง → สรุปผล → ประวัติในเครื่อง
โปรไฟล์สมัครใจ → API/server session → Supabase RPC → ข้อมูลผู้เล่น/อันดับตามสูตรที่รองรับ
ปุ่มเสียง → preference ในเครื่อง → Web Audio
ใช้เสียงนำ CPR → cprAudioGuided → ข้อความในผลสรุป
```

Figma และภาพประกอบไม่มีอำนาจคำนวณคะแนน ปุ่ม UI ต้องเรียก logic เดิม ไม่จำลองคะแนนจาก animation

งานนี้ไม่รวมการเปลี่ยน auth, SQL production, RLS, XP formula, rubric หรือย้ายคะแนนสูตรใหม่เข้าลีดเดอร์บอร์ด หากพบปัญหาจะบันทึกเป็นงานระบบแยกพร้อมแผนทดสอบ/ย้ายข้อมูล ไม่แอบรวมใน redesign

## 10. เกณฑ์ยอมรับและวิธีพิสูจน์

- ตรวจ 320/390/430px, iPad 768/1024px และ desktop 1440px ทั้งแนวตั้งและแนวนอนที่เกี่ยวข้อง ไม่ล้นหรือถูกเมนูบังปุ่ม
- ให้ผู้ทดลองชี้คำสั่งและปุ่มขั้นถัดไปใน AED ได้ภายในประมาณ 3 วินาที เป้าหมายอย่างน้อย 4 ใน 5 คน; เป็นเกณฑ์ทดลอง ยังไม่มีผลวัด
- Keyboard/focus/ชื่อปุ่ม/screen reader เข้าใจสถานะ disabled/loading/feedback ได้ สีไม่เป็นวิธีเดียวในการบอกผล
- เปิดทุกบทและฝึกได้โดยไม่เข้าสู่ระบบ ผลล่าสุดไม่หายหลังปรับ UI
- เล่น AED ทั้ง shock/no-shock และป้องกันกดซ้ำ/ข้าม analysis; เสียงปิดได้และหยุดเมื่อพัก
- Reduced motion ใช้งานได้ ไม่มี animation บังคับให้รออ่าน และไม่เพิ่มเสียง autoplay
- ตรวจ iOS/iPadOS/Android จริง; browser viewport อย่างเดียวไม่ถือว่ารองรับเครื่องจริงแล้ว
- รายงานผลตรวจใหม่ทุกชุด ระบุสิ่งที่ยังไม่ได้ทดสอบ ไม่ใช้ผลทดสอบรุ่นเก่ารับรองรุ่นใหม่

## 11. ความเสี่ยงและมาตรการ

- ดีไซน์หลุดจากสิ่งที่ผู้ใช้ต้องการ: เลือกภาพก่อนแก้โค้ด จำกัดการเปลี่ยนทีละ flow
- ภาพดู AI/คนละชุด: มีภาพต้นแบบเดียว ทดสอบในหน้าจอจริง ไม่ผลิตชุดใหญ่ก่อนเลือกสไตล์
- ภาพสอนผิด: ตรวจแหล่งและผู้เชี่ยวชาญ ถ้ายังไม่ผ่านใช้ข้อความที่ตรวจแล้วก่อน
- เสียงรบกวน: ค่าเริ่มต้นปิด ไม่มีเพลงกลางคำสั่ง AED/1669 เสียงไม่แทนคำเตือน
- ข้อมูลหรือ XP เสีย: แยก presentation จาก logic และทดสอบประวัติเดิมก่อนเผยแพร่
